## Codebase Patterns
- `useGame(socket)` hook wraps a `GameStore` class exported for direct unit testing (see `packages/client/src/hooks/useGame.test.ts`). Drive the store directly rather than rendering the hook — the client project's jsdom env is currently broken in this repo.
- `useRoom(socket, onRoomChange?)` accepts an optional callback invoked on successful `room:create`/`room:join` ack — use this to wire cross-hook cleanup (e.g. GameStore reset) without coupling hooks to each other.
- `useRoom.updateOptions({ maxPlayers?, config? })` emits `room:updateOptions` and resolves with the server `Ack`. Client features that mutate room options should always go through this (don't emit the socket event directly).
- Adding a new workspace package: pnpm-workspace.yaml already globs `packages/*`, but the root `tsconfig.json` "references" array and `vitest.workspace.ts` list are enumerated (not glob) — append the new package to BOTH. Also extend the root `typecheck` script in `package.json` since it runs `tsc -p` against each config explicitly. If the client imports from the new package, add aliases to `packages/client/tsconfig.json` paths.
- `ClientGamePlugin.meta` is a `Pick<>` of `GameMeta`. If you need a new meta field client-side, add it to the Pick list in `packages/shared/src/types/engine.ts` — runtime data is the full meta object, the Pick just controls public typing.
- `App.tsx` is the orchestrator: call `useGame` before `useRoom` if the latter needs a callback from the former.
- `GameLogProvider` (packages/game-ui/src/log/GameLogContext.tsx) auto-clears its entries when `defaultNs` prop changes — so per-game log isolation is automatic once the host sets `defaultNs` to the game's namespace.
- macOS-local only: `pnpm test` surfaces "Unhandled Error … html-encoding-sniffer" failures from jsdom. These BREAK test *collection* in a package that opts into `environment: 'jsdom'` from scratch (see games/yahtzee attempt) — tests ran 0/0 on local. CI on ubuntu is unaffected. Workaround: keep game packages on `environment: 'node'`, extract UI gating logic into pure helpers (e.g. `shouldShowOwnScoreRows` in games/yahtzee/shared.ts) and unit-test those in logic.test.ts.
- Biome baseline on this branch has 4 pre-existing errors in `packages/game-ui/src/header/GameHeader.tsx`, `packages/game-ui/src/theme/playerColors.ts`/`.test.ts`, and `prd.json`. Not introduced by ralph stories — leave them unless a story explicitly touches those files.
- Engine `EngineEvent` is exported from `packages/shared/src/types/engine.ts`. `END_GAME` now carries optional `ties?: string[][]`; consumers in GameRoom treat any tie group containing the rank-1 player as a shared first place. Existing games that don't emit `ties` keep their win/loss behavior unchanged.
- `GameRoom.ledger.test.ts` uses `createTestDb()` and `vi.doMock('../db/index.js', ...)` pattern — integration tests against a real postgres. Poll the ledger (~20ms intervals, 50 iterations) since `recordPoints` is fire-and-forget.
- In pure game-logic changes (e.g. games/liar-bar/logic.ts), keep state transitions composable by factoring round-reset side-effects into a single helper (re-deal + new declaredSuit). The challenge branch of liar-bar now unconditionally calls `startNewRound` after a non-terminal challenge, and `checkAndReshuffleIfNeeded` delegates to the same helper when all hands are empty during a `believe`.
- For presentational React components, `renderToStaticMarkup` from `react-dom/server` is a zero-setup unit-test path that avoids the macOS jsdom `html-encoding-sniffer` bug. Works under `environment: 'node'` — assert on the HTML string for class/attr/aria-label checks. Use jsdom only when interaction (fireEvent, useEffect side-effects) is actually under test.
- To add a new Tailwind color utility (`bg-<token>`, `text-<token>`) in `packages/client/src/index.css`, declare BOTH the raw variable in `:root` (e.g. `--piece-red: #d94040;`) AND its `--color-*` alias inside the `@theme inline` block (e.g. `--color-piece-red: var(--piece-red);`). Only one of the two won't make the utility work.
