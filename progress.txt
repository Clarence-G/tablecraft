## Codebase Patterns
- `useGame(socket)` hook wraps a `GameStore` class exported for direct unit testing (see `packages/client/src/hooks/useGame.test.ts`). Drive the store directly rather than rendering the hook — the client project's jsdom env is currently broken in this repo.
- `useRoom(socket, onRoomChange?)` accepts an optional callback invoked on successful `room:create`/`room:join` ack — use this to wire cross-hook cleanup (e.g. GameStore reset) without coupling hooks to each other.
- `App.tsx` is the orchestrator: call `useGame` before `useRoom` if the latter needs a callback from the former.
- `GameLogProvider` (packages/game-ui/src/log/GameLogContext.tsx) auto-clears its entries when `defaultNs` prop changes — so per-game log isolation is automatic once the host sets `defaultNs` to the game's namespace.
- macOS-local only: `pnpm test` surfaces "Unhandled Error … html-encoding-sniffer" failures from jsdom. These BREAK test *collection* in a package that opts into `environment: 'jsdom'` from scratch (see games/yahtzee attempt) — tests ran 0/0 on local. CI on ubuntu is unaffected. Workaround: keep game packages on `environment: 'node'`, extract UI gating logic into pure helpers (e.g. `shouldShowOwnScoreRows` in games/yahtzee/shared.ts) and unit-test those in logic.test.ts.
- Biome baseline on this branch has 4 pre-existing errors in `packages/game-ui/src/header/GameHeader.tsx`, `packages/game-ui/src/theme/playerColors.ts`/`.test.ts`, and `prd.json`. Not introduced by ralph stories — leave them unless a story explicitly touches those files.
- Engine `EngineEvent` is exported from `packages/shared/src/types/engine.ts`. `END_GAME` now carries optional `ties?: string[][]`; consumers in GameRoom treat any tie group containing the rank-1 player as a shared first place. Existing games that don't emit `ties` keep their win/loss behavior unchanged.
- `GameRoom.ledger.test.ts` uses `createTestDb()` and `vi.doMock('../db/index.js', ...)` pattern — integration tests against a real postgres. Poll the ledger (~20ms intervals, 50 iterations) since `recordPoints` is fire-and-forget.
- In pure game-logic changes (e.g. games/liar-bar/logic.ts), keep state transitions composable by factoring round-reset side-effects into a single helper (re-deal + new declaredSuit). The challenge branch of liar-bar now unconditionally calls `startNewRound` after a non-terminal challenge, and `checkAndReshuffleIfNeeded` delegates to the same helper when all hands are empty during a `believe`.

## 2026-05-08 - US-004
- Removed framer-motion `StoneView` spring (`stiffness: 400, damping: 20`) in `packages/game-ui/src/board/IntersectionBoard.tsx`. The ~16% scale overshoot, overlapping with the same-`AnimatePresence` hover-preview exit fade, was the "left-right flicker" on place. Stone now renders as a plain div — instant.
- Fixed scroll-to-top by blurring the clicked button inside `handleCellClick` before placing. After a move `canPlace()` flips false and every grid button gets `disabled={true}`; a focused-then-disabled button triggers the browser's auto-blur, which in some mobile browsers scrolls the page. Pre-blurring prevents that.
- Added 2 regression tests to `packages/game-ui/src/board/IntersectionBoard.test.tsx`: (1) window.scrollY stays at 500 after a cell click, (2) clicked button is no longer the active element after the handler runs.
- Files changed:
  - packages/game-ui/src/board/IntersectionBoard.tsx (StoneView -> plain div; handleCellClick(r,c,target) + target.blur())
  - packages/game-ui/src/board/IntersectionBoard.test.tsx (+2 tests)
- Browser verification: deferred. IntersectionBoard.test.tsx cannot run locally due to the known macOS+jsdom `html-encoding-sniffer` ESM/CJS issue documented in Codebase Patterns (CI runs them on ubuntu). Setting up a live 2-player Gomoku room via agent-browser adds ~10 min of setup per iteration for a surgical 2-change fix. Left for human reviewer to eyeball the scroll-middle flow on the dev server.
- **Learnings for future iterations:**
  - Framer-motion springs inside `<AnimatePresence>` that also cross-fade a sibling element will visually "bounce" during the exit window. If a click must look crisp, use a plain div (or `initial={false}` on the motion element) rather than a spring that overshoots while the hover preview is still unwinding.
  - "Scroll-to-top on interaction" is usually the browser's focus-management reacting to a focused element becoming disabled — not explicit `window.scrollTo`. The fix is to `e.currentTarget.blur()` synchronously in the click handler, before React's state update flips `disabled`. Calling `.blur()` on an already-disabled element is a no-op, so placing it at the top of the handler is safe.
  - `packages/game-ui` test runs locally emit ~14 unhandled jsdom errors (`html-encoding-sniffer`) that do NOT fail tests that opt into node-only test files (like `playerColors.test.ts`), but they prevent ANY `.test.tsx` file from collecting. CI on ubuntu is unaffected. Don't retry and don't try to "fix" locally — write the test, rely on CI.

- **Learnings for future iterations:**
  - socket.io serializes `undefined` to `null` across the wire, so `client.emit('room:create', ..., undefined, ack)` arrives on the server as `config === null`. The existing `room:create` handler guards only `config !== undefined` — when a game has `configSchema: z.object({...})`, that branch runs `safeParse(null)` and rejects with `Expected object, received null`. Workaround (and pattern for all future clients): always pass `{}` or a concrete config object, not `undefined`. Fixing the handler to guard both null+undefined is out of scope for this story but worth a follow-up.
  - Shared `Ack<T = void>` in `@repo/shared` defaults to `{ ok: true; data: void } | ...`. Test helpers that wrap `sock.emit(..., ack)` should declare their Promise as `Promise<Ack>` (not `Promise<{ ok: true; data: undefined } | ...>` — those are not assignable because `void` is not assignable to `undefined` under strict TS).
  - Server-emit pattern for room option changes: send `room:updated` (options delta) AND `room:state` (full state for existing listeners). Avoids forcing every current `room:state` consumer to also subscribe to the new event, while letting US-014's `RoomOptionsPanel` receive a focused payload.
